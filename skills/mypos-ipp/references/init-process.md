# INIT, END_INIT, and PROCESS

These methods are called **by the terminal (POS)**, not by the caller (external service/application). They implement the Slave mode startup handshake. Understanding them is required when building a Slave mode service that the terminal connects to.

---

## INIT

The terminal sends INIT when it starts up to discover and register with the connected external service. The service must respond. The terminal sends its serial number, printer capability, and connection mode (Slave or Cash Register) along with the SSL certificate fingerprints the service should use for acquiring host connections.

### Message from POS — Request

| Property | Presence | Description |
|----------|----------|-------------|
| `PROTOCOL` | M | `IPP` |
| `VERSION` | M | `202` |
| `METHOD` | M | `INIT` |
| `SID` | M | UUID generated by the terminal |
| `SN` | M | Terminal serial number |
| `PRINTER` | M | `0`=no printer, `1`=has printer |
| `OWN_CONNECTION` | M | `0`=Slave mode (service provides network), `1`=Cash Register mode (terminal has its own network) |
| `PRIMARY_CHAIN` | C | Slave mode: up to 4 certificate fingerprints (20 bytes each), separated by `;`. Used for all methods except UPDATE |
| `SECONDARY_CHAIN` | C | Slave mode: same format as PRIMARY_CHAIN. Used only for the UPDATE method |

### Response from Service — Stage 1

| Property | Presence | Description |
|----------|----------|-------------|
| `PROTOCOL` | ME | |
| `METHOD` | ME | |
| `SID` | ME | |
| `STATUS` | M | `0`=OK, `2`=syntax error, `3`=unsupported param, `4`=unsupported method, `14`=internal error, `37`=fingerprint not found, `38`=unsupported version |
| `STAGE` | M | `1` |

---

## END_INIT

The service sends END_INIT to confirm that the initialization sequence is complete. This is the final message from the service in the INIT handshake. Sent only when INIT was accepted (STATUS=0).

### Message from Service — Request

| Property | Presence | Description |
|----------|----------|-------------|
| `PROTOCOL` | M | `IPP` |
| `VERSION` | M | `202` |
| `METHOD` | M | `END_INIT` |
| `SID` | M | New UUID |
| `STATUS` | M | `0` (OK) |

The terminal does not send a response to END_INIT.

---

## PROCESS

The terminal sends PROCESS to pre-notify the service that it is about to begin processing a payment request. The service receives this message before the terminal sends the actual payment method (e.g., PURCHASE, REFUND). This allows the service to prepare its network connections.

### Message from POS — Request

| Property | Presence | Description |
|----------|----------|-------------|
| `PROTOCOL` | M | `IPP` |
| `VERSION` | M | `202` |
| `METHOD` | M | `PROCESS` |
| `SID` | M | UUID generated by the terminal |
| `SN` | M | Terminal serial number |
| `OWN_CONNECTION` | M | `0`=Slave mode, `1`=Cash Register mode |
| `CHAIN` | C | Slave mode: fingerprints of the certificate chain to use for this request |
| `IP` | C | Slave mode: acquiring host IP address |
| `PORT` | C | Slave mode: acquiring host port |

### Responses — Stages 2–5

The service receives intermediate stage messages during the actual payment processing:

| Stage | STATUS values | Notes |
|-------|--------------|-------|
| `2` | `0`=card waiting, `5`=no card found, `6`=unsupported card, `7`=card chip error, `13`=user cancel, `14`=internal error | Card interaction |
| `3` | `0`=PIN check online, `9`=invalid PIN, `10`=max PIN count exceeded, `11`=PIN check online, `13`=user cancel, `14`=internal error | TRIES_LEFT(C) if STATUS≠0,11,13 |
| `4` | `0`=OK, `13`=cancel, `14`=internal error, `15`=comm error, `31`=update do not wait, `32`=update wait | DATA(C) for STATUS=0/31/32. Applicable for OWN_CONNECTION=0. STATUS=31: send DATA but don't wait for host response; STATUS=32: send DATA and wait for host response |
| `5` | `0`=OK, `13`=cancel, `14`=internal error, `15`=comm error, `29`=no updates, `30`=update unsuccessful | Final result |

## Slave Mode Startup Sequence

```
Terminal boots
  → Terminal sends INIT (with SN, PRINTER, OWN_CONNECTION, PRIMARY_CHAIN, SECONDARY_CHAIN)
  ← Service responds with STATUS=0, STAGE=1

  ← Service sends END_INIT (STATUS=0)
  (No response expected)

Terminal is ready to receive payment commands from caller
  → Terminal sends PROCESS (pre-notification)
  ← Service prepares network connections

  Caller sends PURCHASE / REFUND / etc.
  → Terminal processes, sends STAGE=4 DATA for Slave proxy
  ← Service proxies DATA to acquiring host
  → Terminal eventually sends STAGE=5 (final result)
```
